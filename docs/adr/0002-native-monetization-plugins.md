# Native monetization plugins (AdMob, RevenueCat)

AdMob and RevenueCat have no web SDK, so the revive offer only exists on the Capacitor iOS/Android builds — the GitHub Pages web build keeps the placeholder ad-break unchanged, gated behind `Capacitor.isNativePlatform()`. We use `@capacitor-community/admob` (the actively-maintained community plugin; there is no official first-party AdMob plugin) and RevenueCat's own `@revenuecat/purchases-capacitor`, fetched by product identifier via `getProducts`/`purchaseStoreProduct` rather than through an Offering, since no Offering is configured in the RevenueCat dashboard yet. Both ship SPM support alongside CocoaPods, so `pnpm sync` slotted them straight into the existing `ios/App/CapApp-SPM/Package.swift` with no Podfile migration.

Revive is a fresh consumable purchase every death, not a stockpiled balance: an earlier pass tried a purchasable pack of revive tokens, but RevenueCat's Virtual Currency feature — the natural home for an account-tied balance — only lets the *client* read a balance; spending one requires a backend calling RevenueCat's REST API with a secret key, which this project doesn't have and isn't taking on for this feature. Buying a revive on every death sidesteps needing any balance at all.

The joke placeholder ad-break (`AdBreak`) is no longer the only path: on native, `GameScene.endRun` now awaits a real `AdMob` interstitial (`ads.showInterstitial()`) before showing the results screen, and passes `AdBreak.show` an `instant: true` flag that swaps the fake ad-frame and 5-second lock for a plain, immediately-clickable "Continue" — the real ad already gated the moment. The web build (and any native init failure) still gets the original joke, unchanged, via `instant: false`.
